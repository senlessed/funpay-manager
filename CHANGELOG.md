# Изменения

## 0.1.0.dev6 — 2026-10-30

- Мастер группы показывает адресованную `/bindgroup@имя_бота` и предупреждение
  об отмене кода при закрытии окна и запрете анонимности администратора.
- Полученная команда привязки больше не отклоняется молча для известного владельца:
  статус и подтверждение отправляются ему в личный чат, с ограничением частоты.
- Диагностика обычной группы без тем, неактивного/неверного кода, прав и уже привязанной группы.
- Команды других пользователей, анонимные, пересланные и для другого бота игнорируются.
- 155 автономных тестов, включая прохождение реального aiogram Dispatcher с fake Bot API.

## 0.1.0.dev5 — 2026-10-30

- Исправлен глобальный X-Requested-With: главная страница профиля теперь
  запрашивается как HTML, а runner/history — как AJAX. FunPay возвращал фрагмент
  без body/data-app-data при AJAX-запросе главной, что срывало проверку профиля.
- Контракт воспроизведён на публичной странице без ключей; добавлен regression test
  авторизации, списка чатов и истории. 147 автономных тестов.
- Реальная авторизация владельца после исправления требует повторной проверки.

## 0.1.0.dev4 — 2026-10-30

- Вместо общего отказа подключения FunPay: безопасные коды для авторизации,
  HTTP 401/403/429, TLS, сети, таймаута, формата и Credential Manager.
- Принимается отдельное значение cookie или `golden_key=значение`; целый Cookie
  header и некорректные значения отклоняются до запроса и остановки служб.
- Ключ нормализуется до проверки и сохранения; коды в UI/логах не содержат секретов.
- Сборка в отдельный каталог позволяет не заменять работающий EXE.
- 146 автономных тестов; успех авторизации на реальном аккаунте не подтверждён.

## 0.1.0.dev3 — 2026-10-30

- Одноразовая привязка закрытой forum-группы владельцем, проверка прав и bot ID.
- Темы по чатам, SQLite mappings, резервирование до внешнего создания и ручное восстановление.
- Очередь зеркал private/topic/site с подавлением эха; неизвестный результат без автоповтора.
- Ответы владельца из известных тем через общий opt-in outbox и повторную авторизацию.
- Статусы зеркал, явное подтверждение повтора, persistent Telegram cooldown.
- Миграция 3 → 4, безопасный restore схем 1–4 с отключением Topics.
- 127 автономных тестов. Живые Telegram/FunPay не проверены.

## 0.1.0.dev2 — 2026-10-30

- Фоновый SyncWorker: до 5 историй за цикл, постоянные курсоры и тихий baseline.
- Общий интервал запросов FunPay, backoff/jitter, пауза при auth/CAPTCHA.
- Отдельная очередь Telegram-уведомлений о входящих и статусе исходящих.
- Дедупликация, persistent retry_after, unknown без слепого повтора, проверка владельца.
- Флажки и статус Windows, pause/resume в трее, раздел уведомлений в Telegram.
- Миграция SQLite 2 → 3, restore схем 1–3 с отключением автоматизаций.
- 96 автономных тестов; 100 mock-событий с перезапуском и ошибкой доставки.

## 0.1.0.dev1 — 2026-10-30

- Миграция SQLite 1 → 2: чаты, история, очередь и контексты ответа.
- История из FunPay по запросу, локальное сохранение, пагинация и направление сообщений.
- Ответ через конкретный prompt бота, TTL, /cancel, дедупликация Telegram updates.
- Opt-in отправка в Windows, FIFO по чату, консервативный unknown без слепого повтора.
- Отдельный messaging adapter с подтверждением нового remote ID; только mock/fixture проверки.
- UUID операций и route_key чатов защищают устаревшие callbacks после restore.
- Restore staged copy выключает отправку и исключает повтор устаревшей очереди.

## Read-only FunPay и рабочий бот — 2026-10-30

- Автозапуск личного бота после привязки и при старте приложения, reconnect.
- Owner-only команды /menu, /status; inline «Чаты», «Статус», пагинация.
- Сохранение polling offset, backoff и закрытие сессий при выходе/restore.
- Свой асинхронный read-only адаптер FunPay: профиль и превью до 50 чатов.
- Локальное подключение golden_key, Credential Manager, cache и ограничение запросов.
- Старый FunPayAPI с фиксированными старыми HTTP-зависимостями не включён в сборку.
- Реальное подключение к Telegram/FunPay в этом этапе не проверялось.

## Telegram setup — 2026-10-30

- Мастер проверки токена getMe и отказ при активном webhook.
- Код владельца с TTL/лимитом попыток и защитой от повторного назначения.
- Защищённое сохранение токена по namespace профиля после подтверждения владельца.
- Автотесты с mock Telegram/Vault, без реальных сетевых действий.

- SQLite миграция, настройки, backup; тестовый FunPay adapter.
- Проверки без ключей и скрипты preview-сборки. Интеграции ещё не включены.
