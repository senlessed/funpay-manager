# FunPay Telegram Manager

Бесплатное локальное приложение для Windows 10/11 x64. Цель — управлять FunPay
через собственного Telegram-бота и закрытую группу с темами, без VPS и веб-панели.

**Статус: 0.1.0.dev0 — Windows-основа для разработки, не готовый менеджер продаж.**
Telegram и FunPay ещё не подключаются. Нет мастера настройки, Topics, очереди
сообщений, заказов и автоподнятия. Не вводите токены в чат, исходники или конфиги.
Подробные задачи и критерии: [PLAN.md](PLAN.md), решения: [ARCHITECTURE.md](ARCHITECTURE.md).

## Что уже работает

- Русское окно со статусом компонентов, светлая/тёмная тема.
- Трей: скрытие при закрытии, возврат, полный выход.
- Один экземпляр на каталог данных; независимый asyncio backend.
- SQLite с атомарной миграцией, WAL, настройками, backup и восстановлением.
- Добровольный автозапуск EXE в трей и исправление пути после перемещения.
- Ротация логов, интерфейс адаптера FunPay и mock для автономных тестов.
- Скрипт Windows onefile-сборки и CI для проверок/preview-артефакта.

## Запуск из исходников

Нужен Python 3.12+ x64 на Windows. PowerShell в каталоге проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.lock
.\.venv\Scripts\python.exe -m pip install --no-deps -e .
.\.venv\Scripts\python.exe -m funpay_manager
```

Lock-файл фиксирует установленный и проверенный набор для Python 3.12 Windows x64.
Он включает инструменты разработки и aiogram для будущей интеграции. Production
FunPayAPI пока не устанавливается. Диапазоны в pyproject.toml — границы совместимости,
не утверждение, что каждая комбинация проверена. Обновления lock проходят тесты.

## Данные и безопасность

По умолчанию `%LOCALAPPDATA%\FunPayTelegramManager\`: `data/funpay.db`, `logs/`,
`backups/`, `config/`. Для тестового профиля можно задать `FPTM_DATA_DIR`.
База не находится внутри EXE или временной распаковки PyInstaller. Кнопка резервной
копии использует SQLite backup API. Восстановление доступно по кнопке после
подтверждения: проверяются целостность и схема, предыдущее состояние сохраняется
в `backups/before-restore-*.db`. Копия должна быть создана этой версией приложения.
Копии базы могут содержать личные данные, храните их с теми же правами, что профиль.

Будущие секреты хранятся только Windows Credential Manager; обёртка уже написана,
но UI их пока не запрашивает. Журнал не содержит текста сетевых исключений.
Настройка темы сохраняется в SQLite. Автозапуск включается пользователем в окне
собранного EXE через HKCU Run, без прав администратора. После перемещения EXE
откройте его вручную и нажмите «Обновить путь автозапуска». В исходниках включение
недоступно. Windows может задерживать запуск или отключить его в диспетчере задач.

## Telegram, FunPay, Topics и автоподнятие

Подключение будет добавлено мастером: токен от [BotFather](https://t.me/BotFather),
одноразовый код владельца, локальный ввод FunPay golden_key и необязательная
закрытая супергруппа. Ключ FunPay — сессионный секрет: не пересылайте его боту.
Для Topics нужны forum supergroup и право бота управлять темами. Все участники
группы могут читать переписки. Поднятие будет отключено по умолчанию и станет
доступно только после проверки API, лимитов и сохранения расписаний.

В этой версии эти операции недоступны: работающие инструкции появятся вместе
с реализацией, без фиктивных кнопок. Программа должна быть запущена на компьютере,
для сетевых функций понадобятся интернет, доступ к Telegram и FunPay.

## Проверки и сборка

```powershell
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m ruff format --check .
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m funpay_manager --smoke-test
$env:PATH = "$PWD\.venv\Scripts;$env:PATH"
.\scripts\build.ps1
```

Выход: `dist/FunPayManager.exe` и `dist/SHA256SUMS.txt`. Smoke без ключей проверяет
окно offscreen, миграцию временной базы и завершение backend; данные профиля не
меняет. CI собирает preview-артефакты, релизы не публикует. Фактические результаты
и непроверенные сценарии находятся в [docs/VALIDATION.md](docs/VALIDATION.md).

## Частые ошибки и обновление

- «Уже запущено»: откройте существующий экземпляр через значок трея.
- Нет значка трея: окно остаётся основным способом управления, закрытие завершает
  программу. Проверьте скрытые значки Windows.
- База более новой версии: верните новую версию программы, не понижайте схему вручную.
- Ошибка backend: смотрите тип операции в локальных логах. Не отправляйте базу или
  секреты в публичные Issues.

Обновление основы — полное завершение через трей, backup, замена EXE. Автоматическая
проверка GitHub Releases ещё не подключена. Скриншоты и пользовательское руководство
добавляются после реализации мастера. Лицензия собственного кода GPL-3.0-only;
подготовка binary notices описана в [docs/DEPENDENCIES.md](docs/DEPENDENCIES.md).
