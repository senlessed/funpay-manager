# FunPay Telegram Manager

Бесплатное локальное приложение для Windows 10/11 x64. Цель — управлять FunPay
через собственного Telegram-бота и закрытую группу с темами, без VPS и веб-панели.

**Статус: 0.1.0.dev6 — версия для разработки, не готовый менеджер продаж.**
Доступны настройка Telegram, привязка владельца, рабочее меню бота и адаптер
чтения списка чатов FunPay. Реальное подключение FunPay ещё требует проверки.
Добавлены локальная история и очередь текстовых ответов. Отправка по умолчанию
выключена. Добавлены фоновая синхронизация и личные Telegram-уведомления.
Добавлены Telegram Topics; живые интеграции ещё не проверены. Заказы и автоподнятие не реализованы.
Не вводите токены в чат, исходники или конфиги.
Подробные задачи и критерии: [PLAN.md](PLAN.md), решения: [ARCHITECTURE.md](ARCHITECTURE.md).

## Что уже работает

- Русское окно со статусом компонентов, светлая/тёмная тема.
- Мастер Telegram: проверка токена, код владельца, защищённое хранение.
- Личный бот: /menu, /status, inline статус и список чатов с пагинацией.
- Локальное подключение FunPay по golden_key, только чтение профиля и превью чатов.
- История чата по запросу, сохранение в SQLite, ответы через долговечную очередь.
- FIFO по чату, дедупликация Telegram, unknown без автоматического повтора.
- Фоновая синхронизация с постоянными курсорами и тихим первым чтением истории.
- Отдельная SQLite-очередь уведомлений о входящих сообщениях и результате отправки.
- Привязка закрытой forum-группы, темы покупателей и долговечная очередь зеркал.
- Ответы владельца из известной темы, ручное восстановление привязки без слепых повторов.
- Трей: скрытие при закрытии, возврат, полный выход.
- Один экземпляр на каталог данных; независимый asyncio backend.
- SQLite с атомарной миграцией, WAL, настройками, backup и восстановлением.
- Добровольный автозапуск EXE в трей и исправление пути после перемещения.
- Ротация логов, интерфейс адаптера FunPay и mock для автономных тестов.
- Скрипт Windows onefile-сборки и CI для проверок/preview-артефакта.

## Запуск из исходников

Нужен Python 3.12+ x64 на Windows. PowerShell в каталоге проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.lock
.\.venv\Scripts\python.exe -m pip install --no-deps -e .
.\.venv\Scripts\python.exe -m funpay_manager
```

Lock-файл фиксирует установленный и проверенный набор для Python 3.12 Windows x64.
Он включает инструменты разработки, aiogram, aiohttp и BeautifulSoup. Старый пакет
FunPayAPI не устанавливается: используются собственные раздельные адаптеры чтения и записи.
Диапазоны в pyproject.toml — границы совместимости,
не утверждение, что каждая комбинация проверена. Обновления lock проходят тесты.

## Данные и безопасность

По умолчанию `%LOCALAPPDATA%\FunPayTelegramManager\`: `data/funpay.db`, `logs/`,
`backups/`, `config/`. Для тестового профиля можно задать `FPTM_DATA_DIR`.
База не находится внутри EXE или временной распаковки PyInstaller. Кнопка резервной
копии использует SQLite backup API. Восстановление доступно по кнопке после
подтверждения: проверяются целостность и схема, предыдущее состояние сохраняется
в `backups/before-restore-*.db`. Поддерживаются копии схем 1–4. Копия сначала
подготавливается отдельно: отправка выключается, queued/sending становятся unknown,
старые запросы ответа удаляются. Старый снимок не может автоматически повторить
сообщения, которые были доставлены уже после создания бэкапа. Синхронизация и
уведомления и Topics после restore также выключены; при возобновлении история заново
снимается тихой начальной точкой, без пересылки старых сообщений.
Копии базы могут содержать личные данные, храните их с теми же правами, что профиль.

Токен Telegram вводится в скрытом поле мастера, проверяется getMe и сохраняется
после подтверждения владельца только в Windows Credential Manager. Пространство
секретов привязано к каталогу профиля; перенос базы в другой профиль не переносит
токен. Журнал не содержит текста сетевых исключений.
Настройка темы сохраняется в SQLite. Автозапуск включается пользователем в окне
собранного EXE через HKCU Run, без прав администратора. После перемещения EXE
откройте его вручную и нажмите «Обновить путь автозапуска». В исходниках включение
недоступно. Windows может задерживать запуск или отключить его в диспетчере задач.

## Telegram, FunPay, Topics и автоподнятие

При первом запуске или по кнопке «Настроить Telegram» введите токен отдельного
бота от [BotFather](https://t.me/BotFather). Затем в течение 5 минут отправьте
показанную команду `/start КОД` этому боту в личном чате. Код одноразовый,
случайный, принимает только обычные личные сообщения пользователя. Первый
случайный отправитель владельцем не становится. Не запускайте тот же токен в другом
приложении. Активный webhook не удаляется: мастер отклонит такой бот.

После привязки токен скрыт, идентификаторы сохраняются после перезапуска.
Перепривязка уже настроенного владельца заблокирована. После кнопки «Готово» бот
запускается автоматически. Отправьте ему `/menu` в личном чате: доступны «Чаты» и
«Статус». Личное меню доступно только владельцу в личном чате; группа настраивается отдельно.
При повторном запуске приложения токен читается из Credential Manager. Кнопка
«Переподключить Telegram» позволяет повторить запуск после отзыва токена/конфликта.

В окне программы нажмите «Подключить FunPay», введите golden_key.
Инструкция получения cookie находится в диалоге. Проверяется профиль аккаунта;
секрет сохраняется только после успешной проверки. Затем в боте откройте «Чаты».
Показываются до 50 последних доступных чатов, по 5 на страницу, с превью последнего
сообщения. Данные списка кэшируются на 30 секунд. Кнопка «История» загружает до 100
последних доступных сообщений и сохраняет их локально; страницы показывают по 5.
Обновление с сайта ограничено 10 секундами на чат; при недоступности сайта остаётся
локальная копия. Это не обещание полной истории. Вложения отображаются типом,
без загрузки файлов. Даты доставки не выдумываются.
Новый адаптер проверен на fixtures и mock HTTP-контракте, не на живом аккаунте:
при изменении HTML, CAPTCHA или блокировке подключение может не сработать.
Защита сайта не обходится. При ошибке войдите на FunPay вручную.
Ключ FunPay — сессионный секрет: не пересылайте его боту.
Для Topics нужны forum supergroup и право бота управлять темами. Все участники
группы могут читать переписки. Поднятие будет отключено по умолчанию и станет
доступно только после проверки API, лимитов и сохранения расписаний.

Для текстовых ответов включите «Разрешить отправку сообщений из очереди в FunPay»
в окне Windows и подтвердите действие. В боте откройте историю → «Ответить» и
ответьте на конкретный запрос бота в течение 15 минут. Обычный текст вне такого
ответа не отправляется. `/cancel` отменяет текущие запросы ввода, а уже сохранённая
операция отменяется в разделе «Очередь». Текст сначала сохраняется в SQLite;
«Сохранено в очереди» ещё не означает доставку. Статус проверяется в «Очереди».

Статусы: queued → sending → sent / failed / unknown. При unknown сообщение могло
дойти: слепого повтора нет, следующие сообщения этого чата ожидают. Проверьте сайт,
затем закройте операцию без повтора по кнопке с подтверждением. Другие чаты продолжают
работать. После обычного рестарта queued возобновляются при включённой отправке,
прерванные sending становятся unknown. Подключение нового ключа и restore выключают
отправку. Выключение флажка не гарантирует отмены уже начатого запроса.

Сетевая отправка проверена только на mock/fixtures, не на живом FunPay. Никаких
реальных сообщений в автоматических проверках не отправлялось.
Подробнее: [docs/MESSAGING.md](docs/MESSAGING.md).

## Фоновая синхронизация и уведомления

После подключения FunPay синхронизация и уведомления владельцу включены по
умолчанию. В Windows есть независимые флажки для их отключения; в трее — пауза
и возобновление синхронизации. Telegram-раздел «Уведомления» показывает последние
10 событий и их статусы. Ошибка уведомления не останавливает чтение FunPay и очередь ответов.

Один цикл читает доступный список до 50 чатов и обновляет до 5 историй; следующая
попытка — через 30 секунд после завершения цикла плюс небольшой jitter. Все запросы
FunPay, включая ручные действия, разделяет общий интервал не менее 2 секунд.
Часть слотов зарезервирована для старых проверок, поэтому одинаковые превью
не мешают позднее обнаружить новое сообщение с тем же текстом. Это не мгновенная
синхронизация всех чатов и не гарантия полной истории: источник даёт ограниченный фрагмент.

Первое чтение каждого чата из начального списка проходит без уведомлений. Пока
чат ещё не получил начальную точку, входящие за этот период тоже входят в неё.
В новых обнаруженных позже чатах уведомляется только последнее входящее сообщение.
Собственные ответы с сайта/из программы сохраняются в истории и не пересылаются
назад как новые входящие. При истёкшей сессии/CAPTCHA чтение и запись приостанавливаются;
проверьте сайт вручную и возобновите синхронизацию.

Уведомления идут только привязанному владельцу через того же бота, без второго polling.
Событие и курсор сохраняются одной транзакцией. При известном лимите Telegram
ожидание сохраняется между запусками; при неопределённой доставке уведомление
становится unknown и автоматически не повторяется. Выключение уведомлений закрывает
ожидающие события, они не высылаются пачкой после включения. Детали — в
[docs/SYNC.md](docs/SYNC.md). Живые Telegram/FunPay по-прежнему не проверены.

Для Topics нажмите «Подключить закрытую группу с темами» в Windows. Создайте закрытую
супергруппу с темами, без публичного username, геолокации и связанного канала.
Владелец и бот должны быть администраторами; боту нужно право управления темами.
Получите локальный одноразовый код и скопируйте показанную команду
`/bindgroup@ИМЯ_БОТА КОД` в группу от привязанного владельца в течение 5 минут.
Оставьте окно с кодом открытым: закрытие отменяет привязку. В правах администратора
своего аккаунта выключите анонимность, отправляйте от себя. Используется тот же бот,
второй не нужен. Если команда получена, бот сообщает результат владельцу в личном
чате: успех, истёкший/неверный код либо необходимость проверить группу/права.
Все участники группы видят все переписки покупателей.

Новая активность создаёт темы по идентификаторам чатов; старая история массово
не пересылается. Для существующего чата: личный бот → История → Тема.
После отдельного включения отправки в Windows обычный текст владельца в известной
теме ставится в очередь покупателю. Не используйте эти темы для внутренних заметок.
Чужие пользователи, боты, анонимные сообщения и команды не отправляются в FunPay.
При выключенной отправке текст из темы не сохраняется для последующей отправки.

После таймаута создания проверьте группу: тема могла появиться. В разделе «Тема»
даны команда `/attach` для существующей темы и создание новой с подтверждением.
Удалённая/закрытая тема не заменяется автоматически. Повтор зеркала с unknown
требует отдельного подтверждения и может продублировать сообщение только в Telegram.
Отключение группы выключает отправку в FunPay. Подробности — [docs/TOPICS.md](docs/TOPICS.md).

Поднятие лотов пока недоступно. Программа должна быть запущена на компьютере,
для сетевых функций понадобятся интернет, доступ к Telegram и FunPay.

## Проверки и сборка

При отказе подключения FunPay окно показывает безопасный код. `fp_auth_unconfirmed`
означает страницу без подтверждённого профиля; `fp_http_403` — запрет запроса сайтом.
Они не доказывают ошибку Credential Manager. Войдите на сайт вручную и скопируйте
значение golden_key из колонки Value в текущем браузерном профиле. Можно вставить
одно значение или `golden_key=значение`, но не всю строку Cookies. Для диагностики
передавайте только код ошибки, без ключей, cookies и HTML страницы.
`fp_credentials` означает, что профиль проверен, но ключ не удалось сохранить в Windows.

Работающий EXE не заменяется во время сборки. Для отдельного файла используйте
`scripts/build.ps1 -OutputDirectory dist/dev4`. Перед запуском новой версии полностью
выйдите из старой через меню трея: закрытие окна лишь скрывает приложение.

```powershell
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m ruff format --check .
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m funpay_manager --smoke-test
$env:PATH = "$PWD\.venv\Scripts;$env:PATH"
.\scripts\build.ps1
```

Выход: `dist/FunPayManager.exe` и `dist/SHA256SUMS.txt`. Smoke без ключей проверяет
окно offscreen, миграцию временной базы и завершение backend; данные профиля не
меняет. CI собирает preview-артефакты, релизы не публикует. Фактические результаты
и непроверенные сценарии находятся в [docs/VALIDATION.md](docs/VALIDATION.md).

## Частые ошибки и обновление

- «Уже запущено»: откройте существующий экземпляр через значок трея.
- Нет значка трея: окно остаётся основным способом управления, закрытие завершает
  программу. Проверьте скрытые значки Windows.
- База более новой версии: верните новую версию программы, не понижайте схему вручную.
- Ошибка backend: смотрите тип операции в локальных логах. Не отправляйте базу или
  секреты в публичные Issues.

Обновление основы — полное завершение через трей, backup, замена EXE. Автоматическая
проверка GitHub Releases ещё не подключена. Скриншоты и пользовательское руководство
добавляются после реализации мастера. Лицензия собственного кода GPL-3.0-only;
подготовка binary notices описана в [docs/DEPENDENCIES.md](docs/DEPENDENCIES.md).
