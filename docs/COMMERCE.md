# Статусы заказов и автоподнятие — 0.1.0.dev10

## Статусы в темах и фильтры

OrdersWorker читает GET /orders/trade примерно раз в минуту с общим RequestGate.
Разбираются ID заказа/покупателя, явный статус, описание и Decimal-сумма с валютой
(неизвестная валюта/сумма остаётся None). Список ограничен полученной страницей,
полный архив не обещается. При наличии продолжения отдельно читается фильтр paid;
если и он неполный, отсутствие paid не считается доказательством закрытого заказа.

Связь с чатом берётся из подтверждённого node.name users-ID-ID при чтении истории:
один ID должен совпасть с подключённым аккаунтом. Совпадение nickname не используется.
Кеш помечает неувиденные старые заказы unknown, а не закрывает их. Свежий paid имеет
приоритет над другими заказами покупателя. Иначе используется последний известный
статус, с учётом неизвестных записей и полноты active-списка. Данные старше 180 секунд,
сдвиг времени назад, отсутствие связи или отключённое чтение дают unknown.

Названия: «Открытый заказ · ник · ID», «Закрытый заказ · ник · ID», «Возврат · ник · ID»,
«Статус неизвестен · ник · ID». Без хештегов. ID сохраняет различимость одинаковых
ников. Личный список до 50 доступных чатов фильтруется по этим статусам.
Поиск /find продолжает охватывать локальные чаты, без фильтра заказов.

Темы переименовываются постепенно через того же бота, без второго polling.
Перед изменением проверяются bot/owner/account/group и закрытость/права;
последнее имя сохраняется по binding_key + local chat ID. Rename идемпотентен,
при удалённой теме новая автоматически не создаётся. Используется общий cooldown
зеркалирования; при активной очереди сообщений названия могут обновиться позже.

## Автоподнятие

По умолчанию off. В Windows отдельное окно читает свой профиль и показывает
категории опубликованных обычных лотов; chips/игровая валюта исключены.
Флаг отправки сообщений FunPay не разрешает поднятия. Включение автоподнятия
требует выбора категорий и отдельного подтверждения. Интервал 15 минут — 24 часа
является пользовательским интервалом попыток, а не предполагаемым cooldown сайта.

Перед каждым POST адаптер заново читает свои категории и убеждается, что все
выбранные nodes принадлежат текущему аккаунту/game. После этого повторно проверяется
локальный enabled, выбранные nodes и аккаунт. POST /lots/raise всегда содержит
game_id, node_id и явный node_ids[]; модальная форма поднятия не запрашивается,
потому что её запрос тоже способен поднять лоты. Цены, баланс, возвраты не меняются.

Один job за цикл 30 секунд, с общим FunPay RequestGate. Атомарный claim и запись
raise_attempts предшествуют возможному POST. Ack error=false/0 даёт raised; явный
ответ ожидания с распознанными RU/EN часами/минутами/секундами — cooldown. Если
время не распознано, оно не выдумывается: категория останавливается с отказом.
Успех планирует следующую попытку по пользовательскому интервалу. Переключение
режима/интервала не сокращает сохранённое ожидание. Нет серии пропущенных поднятий
за время выключенного компьютера.

Сетевая ошибка чтения до POST допускает позднюю повторную проверку. После начала
POST таймаут/непонятный ответ/отмена дают unknown; при рестарте sending тоже unknown.
Такая категория не повторяется автоматически. Владелец проверяет сайт и может
разрешить новые попытки отдельной кнопкой с подтверждением; сохранённое время
ожидания остаётся. Auth/CAPTCHA выключает режим. Остановка режима не может отменить
уже начатый HTTP-запрос. Секреты, произвольный ответ и текст исключения не логируются.

## Данные и проверки

Schema 5 добавляет orders_cache, chats.buyer_id, lot_schedules и raise_attempts.
Backup/restore схем 1–5; restore выключает orders и auto_raise, незавершённые поднятия
становятся unknown. Смена ключа выключает поднятие. Фоновые задачи отменяются и
закрываются при выходе/восстановлении. Настройки и расписания привязаны к account ID.

Контракты исследованы по [первичному исходнику FunPayAPI](https://github.com/LIMBODS/FunPayAPI/blob/master/FunPayAPI/account.py)
31.10.2026 (get_sells, get_user, raise_lots); собственный async-адаптер не устанавливает эту библиотеку.
Живое чтение продаж/своих категорий проверено; POST поднятия проверен только mocks.
