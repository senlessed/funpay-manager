# Шаблоны ответов — 0.1.0.dev11

## Использование

Windows → «Шаблоны ответов…». Название до 60 символов, короткий текст ответа,
до 50 шаблонов на аккаунт. «Новый», «Сохранить», подтверждённое удаление и пример
с условными значениями. Изменения сохраняются только кнопкой; при работе с БД
редактор временно блокируется. Обычные скобки записываются как `{{` и `}}`.

Поля: `{buyer}` — username чата, `{seller}` — сохранённое имя подключённого аккаунта,
`{chat_id}` — remote chat ID. Используются данные текущего аккаунта/чата; если
нужного поля нет, предпросмотр не создаётся. Итог — plain text, без HTML/URL preview.
Лимит исходного шаблона и результата — 2800 UTF-16 units, чтобы весь показанный
ответ поместился вместе с получателем. При превышении текст отвергается, не обрезается.

Личный бот → история чата → «Шаблоны», страницы по пять. После выбора отображается
получатель (ник и ID) и итоговый текст. Открытие/отмена ничего не отправляет.
«Отправить в FunPay» создаёт операцию в общей очереди, если запись разрешена в Windows.
Статус подтверждения означает создание операции, не подтверждение доставки.
В темах нет нового автоматического обработчика текста: обычные ответы работают как раньше.

## Данные и границы

Schema 6: reply_templates (случайный ID, account ID, title/body/revision) и
template_previews (случайный key, template revision, account/chat/route, bot/owner,
ID сообщения предпросмотра, точный текст, срок, состояние и operation ID).
Сначала сохраняется draft, затем отправляется Telegram-предпросмотр и привязывается
его message ID. Если процесс оборвался до привязки, кнопка не может отправить draft.

Подтверждение делает BEGIN IMMEDIATE и проверяет текущий аккаунт, bot/owner,
private message ID, route_key, revision, TTL и sending_enabled. Снимок текста
не пересчитывается при нажатии: в outgoing_messages копируется только показанный текст.
INSERT operation и смена preview status выполняются одной транзакцией. Повторная
кнопка, в том числе после рестарта и сбоя изменения квитанции Telegram, возвращает
существующую операцию. Даже после её ручного закрытия повтор не создаётся.
Окончательная доставка использует существующий MessageService/FIFO/unknown policy.

TTL — 15 минут, с отказом при откате часов раньше создания. Изменение/удаление
шаблона отменяет draft/ready для него. Конкурентное редактирование защищено revision.
Все кнопки обрабатываются после owner + private guard; перенесённая в другой чат
кнопка или чужой пользователь не получают доступ. Копия кнопки на другом message ID
также не подходит. Подстановка — разбор Formatter.parse с whitelist трёх полей;
нет eval, attribute/index access, conversion и format spec, значения не раскрываются повторно.

Backup включает шаблоны. Restore схем 1–6 отменяет draft/ready и выключает отправку;
queued outgoing снимка становится unknown по общим правилам. Старые кнопки не
возобновляют отправки. Предпросмотры не публикуются в группу, тексты в логи не пишутся.
В этом этапе проверены только mocks и локальная БД; новых реальных сообщений агент не отправлял.
