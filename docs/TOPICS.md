# Telegram Topics — 0.1.0.dev3

Реализовано и проверено на mocks, без настоящих ключей и сообщений покупателям.
Инструкции подключения — в README. Topics необязательны, до привязки выключены;
привязка включает зеркалирование, но не разрешает запись в FunPay.

## Авторизация и маршрутизация

Один BotService получает updates. Код группы живёт в памяти пять минут,
одноразовый, с лимитом попыток. Принять его может только уже привязанный owner.
Проверяются bot/account/owner, закрытая forum-супергруппа и права администраторов.
Отклоняются публичные usernames, связанные каналы и группы с геолокацией.
Проверка не означает, что в группе нет других участников: все они видят переписки.

Мастер показывает адресованную команду `/bindgroup@имя_бота КОД`. Окно с кодом
нельзя закрывать до завершения: закрытие отменяет challenge. Администратор должен
отправлять от своего аккаунта, без анонимности. Статусы полученной команды идут
только известному владельцу в личный чат, без повторения кода. Повторные ошибки
ограничены интервалом 5 секунд; успешное подтверждение не подавляется. Сбой доставки
подтверждения не откатывает сохранённую привязку. Для посторонних/анонимных,
пересланных сообщений и команд другому боту диагностика не отправляется.

Нормальный текст owner из точных group/thread ставится в общий outgoing_messages
только при включённой в Windows отправке. Чужие сообщения, анонимные отправители,
боты, пересылки, сообщения через бота, команды и неизвестные темы игнорируются.
Служебные ответы бота никогда не пересылаются покупателю. Для внутренних заметок
такие темы использовать нельзя. Вне темы текст группы не маршрутизируется.

Перед FunPay POST повторно проверяются сохранённые source_owner_id,
source_binding_key, source_thread_id, актуальный mapping и права в группе.
Отключение/смена привязки не даёт старой операции право отправки в новой группе.
После отключения группы запись в FunPay выключается. Уже начатый запрос может
завершиться; настройки внешнего сервиса и локальная БД не имеют общей транзакции.

## Хранение и восстановление

Schema 4 добавляет telegram_topic_mappings, telegram_message_mappings и
telegram_topic_deliveries. Уникальные ограничения разделяют чаты по local ID и
темам, имена покупателей не служат ключами. binding_key меняется при новой привязке.
Создание сериализовано lock и предварительным SQLite reserve: pending → creating
фиксируется до createForumTopic. Успех сохраняет thread ID и ready.

При таймауте/аварии creating становится unknown: тема могла быть создана.
Слепого создания второй темы нет. Владелец проверяет группу и в личном боте
открывает История → Тема: команда `/attach LOCAL_ID ROUTE_KEY` внутри нужной темы
перепривязывает её. General и тема, уже привязанная к другому чату, не принимаются.
Создание новой темы доступно отдельной кнопкой с подтверждением; прежняя тема
остаётся в Telegram. Telegram API не даёт надёжного перечисления всех тем для
автоматического восстановления. Удалённая/закрытая тема получает invalid;
требуется ручная привязка или подтверждённое создание новой.

Restore поддерживает схемы 1–4, выключает Topics и остальные автоматизации,
переводит ожидающие зеркала снимка в unknown, незавершённое создание тоже в unknown.
Снимок не является основанием для повторной сетевой доставки.

## Очередь зеркал

SyncWorker атомарно сохраняет историю, курсор и новые зеркала. Первый baseline
тихий; вся старая история автоматически не публикуется. Подтверждённые исходящие
из личного бота и с сайта тоже зеркалируются. Ответ из самой темы записывает
mapping исходного Telegram message ID и подавляет его зеркало, включая гонку sync.
Повтор remote message ID не создаёт новое событие. Вложения отображаются типом.

Отдельный worker проверяет bot ID, права и привязку; второго polling нет.
Перед sendMessage сохраняется cooldown 3.2 секунды на группу; retry_after Telegram
сохраняется между запусками. Ожидающие события идут по очереди, недоступная тема
не блокирует другие чаты. Временная ошибка до отправки оставляет queued; отказ
становится failed; неопределённый результат после начала отправки — unknown.
При нарушении прав/закрытости Topics приостанавливаются.

В личном разделе «Тема» видны последние пять статусов зеркал. Для failed/unknown
возможен только ручной повтор с отдельным подтверждением: сообщение могло уже
появиться, поэтому возможен дубль в Telegram. Этот повтор не отправляет текст в
FunPay. Гарантии exactly-once между SQLite и Telegram нет.

Тексты plain text, URL previews отключены, длина ограничена с учётом UTF-16.
Свежие проверки прав уменьшают риск утечки, но не предотвращают изменение состава
или публичности группы между проверкой и внешним запросом.
